# 更新公告与更新日志

[返回目录](../../README.md#目录)

## 自动展示公告

登录后，工作空间和编辑器初始化完成时，尚未在此浏览器展示过的当前版本公告会自动弹出。关闭按钮、右上角叉号与 Esc 都会返回画布，不改变图形、工具、选区、视角或撤销记录，自动保存继续执行。没有画布的空工作空间同样可以查看公告。

## 回看历史更新

普通用户和管理员都能从“设置 → 更新日志”查看当前版本，并展开历史更新。更新日志不依赖账户设置同步成功；它和公告共用随前端发布的静态内容，不请求 GitHub 或额外后台接口。已经打开的旧页面不会轮询新部署或强制刷新。

## 展示进度

公告内容在可见页面中实际展示后，才记录该账号的展示进度。首次使用、首次引入公告功能或新浏览器都只展示当前版本，不逐条弹出历史公告。

进度保存在当前站点的 localStorage，按账号隔离，不跨浏览器或设备同步。每个已展示发布批次写入独立标记，读取最高序号；旧标签页的迟到写入不能降低进度，回滚到较旧版本也不会重复弹窗。

支持 Web Locks 的浏览器按账号协调标签页：一个标签页展示并记录后，等待的标签页跳过公告。storage 事件同步其他标签页的进度。不支持 Web Locks 时仍会读取进度并处理 storage 事件，但同时打开的标签页可能各自显示一次。

浏览器禁止存储或额度不足时，当前页面使用内存记录；关闭后不会在本页重复弹出，刷新或其他标签页可能再次出现。弹窗打开失败不记录成功，页面提供重试，也可从设置查看更新日志。

## 发布新公告

新公告随 `dev` 合入 `main` 的批量版本发布一起准备，完整流程见[开发规范](workflow.md#批量发布)。

维护 [releases.ts](../../src/data/releases.ts)，不需要数据库迁移：

1. 在数组最前方添加发布记录，使用新的稳定 `id` 和大于所有历史记录的整数 `sequence`。同一个版本号再次发布公告，也必须分配新的 ID 和序号；不要重用或下调它们。
2. 填写与 package.json 一致的版本号、发布日期、标题、简述和主要变化。需要用户操作时写入 `actions`，否则保留空数组。历史记录保留原内容。
3. 随应用构建、发布。`currentRelease` 直接引用这份前端中的首条记录，已打开的旧版本不会误展示未来版本内容。

序号用于排列发布批次，不按日期字符串或版本号推测先后。初始化内容中的 2026-10-11 主题记录对应已有发布；2026-10-12 的记录汇总统一设置、缓存和公告功能。

## 验证

`pnpm test:unit` 检查发布记录、账号隔离、乱序写入、回滚及存储异常。`pnpm test:browser tests/browser/release-announcement.spec.ts` 检查自动展示、关闭和刷新、跨标签页与账号、手机滚动、失败重试、云端设置失败时的回看，以及编辑内容、后台保存和撤销记录保持。
